# wowlua-website

The website of [wowlua](https://github.com/DomenikIrrgang/wowlua), the language, compiler, framework and package
manager for World of Warcraft AddOns. Next.js (App Router), every page prerendered.

## Where the content comes from

The wowlua repository is the source of truth. The site renders its files as they are on GitHub, and the running site
keeps up with them: every 5 minutes it checks whether wowlua's main or its releases changed, downloads the new content,
and regenerates its pages from it (at most once a minute per page, on the next visit). A wowlua release or docs change
needs no change, build or deploy here; new docs versions, pages and diagnostic codes appear on their own.

| On the site | From the wowlua repository |
| --- | --- |
| `/docs/…` pages | `docs/**/*.md` (`docs/guide/install.md` is `/docs/guide/install`); the sidebar follows the `##` sections and links of `docs/README.md` |
| `/docs/reference/diagnostics` and `/docs/reference/diagnostics/<code>` | the code tables in `spec/appendix/diagnostics.md`, and each code's explanation and examples in `docs/reference/diagnostics.json` (`cargo xtask diagnostics`) |
| the docs version picker | `main`, plus the newest release of each minor version whose `docs/README.md` has sections (GitHub releases) |
| `/changelog` | `CHANGELOG.md` on main (GitHub release notes if it is missing), commits on main since the last release |
| `/community` | `CONTRIBUTING.md` and `CODE_OF_CONDUCT.md` (linked when they exist), the README's Developing commands, the latest release's changelog |
| landing page facts | `README.md`: intro, install commands, quick start, adoption count, debugging list; the module count from `docs/stdlib/overview.md` |

The specification (`spec/`) is not a part of the site: links to it go to GitHub, and the old `/docs/spec/…`, `/roadmap`
and `/packages` addresses redirect to the nearest docs page (`next.config.ts`). wowlua's `CLAUDE.md` lists the Markdown
the site draws as terminals, compiler output and numbered steps (`lib/markdown.ts`).

Owned by this repository:

- the landing page layout and its headlines (`app/page.tsx`), and the code, terminal and editor samples recorded
  from the compiler (`components/landing/`);
- blog posts, `content/blog/*.md` (front matter: `title`, `date`, `summary`, optional `author`, `tags`, `version`).
  Releases appear in the blog list and the RSS feed (`/blog/rss.xml`) on their own;
- the showcase, `content/showcase/*.json`;
- the "built with wowlua" badges in `public/badge/`, generated by `scripts/make-badges.py` (text outlined from the site's
  fonts, so they render the same anywhere) and offered at `/badge`;
- the design system: `styles/tokens.css`, `styles/design-system.css`, `styles/site.css`, and the site's own
  `styles/markdown.css`.

Links between wowlua's Markdown files are rewritten to site pages; links to other repository files go to GitHub at
the same version. Write the docs so they read well on GitHub too.

## Develop

```sh
npm install
npm run dev            # fetches the content once, then next dev
npm run content        # refresh the content from GitHub
npm run build          # fetch, then prerender every page
```

`scripts/fetch-content.mjs` downloads `README.md`, `CHANGELOG.md`, `CONTRIBUTING.md`, `CODE_OF_CONDUCT.md`, `docs/`,
`spec/` and `examples/` of each docs version, plus the releases and the commits since the last one
(`scripts/content-sync.mjs`). Each download is a snapshot
in `content/.store/`; `content/.cache` points at the current one (neither is committed). The production server runs the
same sync on its own (`instrumentation.ts`). Environment:

- `WOWLUA_LOCAL=../wowlua`: read main from a local checkout's working tree, to preview docs before pushing them.
- `WOWLUA_OFFLINE=1`: build from the existing cache without the network.
- `WOWLUA_REPO=owner/name`: another wowlua repository (a fork).
- `GITHUB_TOKEN`: raises the GitHub API rate limit (60 requests an hour without one; a check makes two, a download
  three).
- `WOWLUA_REFRESH_MINUTES`: how often the running server checks for wowlua changes (default 5 in production, off in
  `next dev`; `0` turns it off).

## Deploy

https://wowlua.dev runs on the `suuui` droplet next to suuui.dev, as its own Compose project in `/opt/wowlua`.
Traefik from the suuui stack terminates TLS and reaches the app over the `suuui_web` network as `wowlua-app`.

`.github/workflows/deploy.yml` builds the image, pushes it to `registry.digitalocean.com/suuui/wowlua-website`, and
deploys it over SSH with a key that can only run `wowlua-deploy <tag>`. It runs on pushes to `main` and by hand.
wowlua changes need no deploy: the image starts from the content fetched when it was built and the server takes it
from there. The image tag names the site commit, and wowlua's main commit and latest release at build time.

| Path in repo | On the droplet |
| --- | --- |
| `deploy/compose.yaml` | `/opt/wowlua/compose.yaml` |
| `deploy/deploy.sh` | `/usr/local/bin/wowlua-deploy` |
| `deploy/deploy-ssh.sh` | `/usr/local/bin/wowlua-deploy-ssh` |

The `production` environment holds the secrets `DIGITALOCEAN_ACCESS_TOKEN` and `DEPLOY_SSH_KEY`, and the variables
`DEPLOY_HOST` and `DEPLOY_KNOWN_HOSTS`.
